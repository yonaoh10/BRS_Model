# תסריט לשיחת בדיקה — בנקאי מול לקוח

מסמך זה נועד לשיחה מבוימת שתקליטו עם חבר, כדי לבדוק שהמערכת קולטת בפועל את מה
שהיא אמורה לקלוט. יש כאן שני תסריטים: **תסריט א'** הוא שיחה תקינה שאמורה לעבור
את שער הזיהוי ואת שער הציות, ו**תסריט ב'** הוא שיחה בעייתית שאמורה **ליפול**
בשניהם ולהיחסם ב‑59 נקודות. מריצים את שניהם — כך רואים גם שהמערכת מזהה איכות
וגם שהיא לא סתם נותנת ציון גבוה לכל דבר.

כל המספרים במסמך **מומצאים**. תעודות הזהות תקינות מבחינת ספרת ביקורת (אחרת
המערכת לא תסמן אותן) אבל אינן שייכות לאיש. אין להשתמש בפרטים אמיתיים של אף אחד.

---

## לפני שמקליטים — שתי נקודות שחוסכות עבודה חוזרת

**1. הקלטה אחת מספיקה.** המערכת מפרידה בעצמה בין הדוברים בקובץ יחיד — זו דרישת
ליבה של הפרויקט והיא ממומשת. פרטים על המודל, על השיטה ועל המגבלות נמצאים
ב‑`docs/diarization_he.md`. אפשר להקליט את השיחה במכשיר אחד, בכל פורמט
ש‑ffmpeg פותח (m4a של אייפון כולל), ולהריץ:

> **ב־Windows** הפקודות במסמך הזה כתובות בתחביר של Linux. ההתאמה:
> `python` ← `.venv\Scripts\python` · `~/rec/` ← `%USERPROFILE%\rec\` ·
> שורה שמסתיימת ב־`\` ← כותבים את הפקודה כולה בשורה אחת ·
> `export HF_TOKEN=...` ← שורה `HF_TOKEN=...` בקובץ `.env` ·
> `echo $?` ← `echo %ERRORLEVEL%` · `open` ← `start` ·
> `grep -o '████' <קובץ> | wc -l` ← `findstr /c:"████" <קובץ>`.

```bash
python -m callqa process --audio ~/rec/call.m4a --call-id REAL001 --banker-id B900
```

**אבל בשביל הבדיקה הראשונה כדאי גם להקליט בנפרד.** אם כל צד מקליט גם את עצמו
מקומית, מקבלים שתי גרסאות של אותה שיחה: הקובץ היחיד שהמערכת תפריד לבד, ומול זה
הפרדה ודאית שמשמשת **תשובה נכונה** למדידה. זו הדרך היחידה לדעת כמה טובה
ההפרדה על השיחות שלכם ולא על קורפוס של מישהו אחר:

```bash
# הקובץ שהמערכת תעבוד עליו
python -m callqa process --audio ~/rec/call.m4a --call-id REAL001 --banker-id B900

# אותה שיחה משני מסלולים, בתור אמת מידה
python scripts/prepare_real_call.py --call-id REF001 \
    --banker-track ~/rec/me.m4a --customer-track ~/rec/friend.m4a
python -m callqa process --audio data/input/calls/REF001.wav --call-id REF001 \
    --banker-id B900 --banker-channel L

# וההשוואה
python scripts/eval_diarization.py --dialog data/output/transcripts/REAL001.dialog.json \
    --reference refs/REAL001.csv
```

כדי שאפשר יהיה ליישר בין השתיים, **ששני הצדדים יספרו "שלוש, שתיים, אחת"
בפתיחה**. ל‑`prepare_real_call.py` יש `--offset` בשניות לתיקון הפרש התחלה.

**2. הסכמה מוקלטת.** בפתיחת ההקלטה תגידו במפורש "השיחה מוקלטת ומתומללת לצורכי
בקרת איכות", והחבר יאשר בקול. זה גם נכון משפטית וגם נבדק על ידי ממד הציות.

## מה המערכת אמורה לתפוס

### פרטים מזהים (שלב הצנזור)

בדקו בקובץ `data/output/redacted/REAL001.json`. כל פריט בטבלה אמור להופיע
מוסתר, והמספר המקורי **לא אמור להופיע שם בכלל**.

| מה נאמר בשיחה | תסריט | תווית מצופה |
|---|---|---|
| 314159260 (ת"ז, נאמר פעמיים) | א' | `<ת"ז:████>` בכל הופעה שתומללה כספרות |
| 054-8765432 | א' | `<טלפון:████>` |
| 481902 (מספר חשבון) | א' | `<חשבון:████>` |
| 4580 4580 4580 4580 | א' | `<כרטיס אשראי:████>` |
| 120000 (סכום) | א' | `<חשבון:████>` — ראו הערה למטה |
| 987654324 (ת"ז) | ב' | `<ת"ז:████>` |
| 03-6547890 | ב' | `<טלפון:████>` |
| 150000 (סכום) | ב' | `<חשבון:████>` |

**ביקורות שליליות** — אלה **לא** אמורים להיחסם: "סניף 812" (שלוש ספרות),
"שלושים שקלים", "עשרה שקלים", "4580" כשהוא נאמר לבדו כארבע ספרות אחרונות.
אם אחד מהם כן נחסם, זה ממצא.

**הערה על הסכומים.** המדיניות היום היא מכוונת־זהירות: כל רצף של שש ספרות או
יותר נחסם כ"חשבון", ולכן גם "120000" ייחסם. זה מכוון — עדיף להסתיר סכום מאשר
לפספס מספר חשבון — אבל שווה לראות את זה בעיניים ולהחליט אם זה מקובל על הבנק.
שתי השורות האלה בתסריטים נועדו בדיוק לזה.

**הערה שנייה, פחות נעימה.** תעודת זהות שתי ספרותיה הראשונות נראות כמו קידומת
קו נייח — 02, 03, 04, 08, 09 — נחסמת, אבל מתויגת `<טלפון:████>` ולא
`<ת"ז:████>`, כי תבנית הטלפון נבדקת לפני תבנית תעודת הזהות. המידע לא דולף,
אבל התווית שגויה ולכן גם הדוח מטעה. ת"ז שמתחילה ב‑01, 05, 06, 07 או בספרה
שאינה 0 מתויגת נכון. אם תרצו לראות את זה בעיניכם — שהלקוח ימסור 033333337
במקום. זה ממצא פתוח בקוד, לא טעות בתסריט.

## איך מריצים

```bash
# 1. עיבוד השיחה ישירות מההקלטה, בלי שום הכנה
python -m callqa process --audio ~/rec/call.m4a --call-id REAL001 --banker-id B900
echo "exit code: $?"   # 0 תקין, 1 דורש בדיקת אדם, 2 כשל

# 4. מה יצא
grep -o '████' data/output/redacted/REAL001.json | wc -l   # כמה פריטים נחסמו
python -m json.tool data/output/features/REAL001.json
python -m json.tool data/output/scores/REAL001.json

# 5. הדוח
python -m callqa report
open data/output/reports/calls/REAL001.html
```

לבדיקה שהשרשרת עצמה עובדת לפני שמקליטים בכלל, אפשר להריץ הכול על הנתונים
הסינתטיים: `python -m callqa run --mock` (כארבע שניות, שש שיחות).

## בדיקה חשובה אחת לפני שסוגרים

פתחו את התמלול הגולמי, `data/output/transcripts/REAL001.json`, וּודאו שהמספרים
שנאמרו בשיחה אכן הופיעו שם **כספרות** ולא כמילים. אם המנוע תמלל "שלוש אחת
ארבע" במקום "314", שום מנגנון צנזור לא יתפוס את זה — וזו הסיבה שבתסריטים
מבקשים לומר גם את הרצף וגם, במקרה הכרטיס, את המספר המלא. אם זה קורה, זו בעיה
בתמלול שצריך לטפל בה לפני שמסיקים משהו על הצנזור.
